# 00 可行性草案：DSH 步骤级消息删除 / 分支插件

> 状态：已锁定 ｜ 版本：v1.1 ｜ 最后更新：2026-11-26
> 上游：[研发流程规范](../../DEVELOPMENT-WORKFLOW.md)（Stage 0）、[开发规范](../../DEVELOPMENT-GUIDELINES.md)
> 项目暂定名：`dsh-step-editor`（见 D-01）

## 1. 背景与来源

| 编号 | 来源 | 内容 |
| --- | --- | --- |
| S-01 | 2026-11-26 对话（本会话） | 公司内网环境，模型上下文受限。某一轮某一步读取大量图片，请求体积超过网关上限被拦截；该错误不被 DSH 识别为 context-overflow，compaction 不触发。中断该轮再开新轮，请求仍从 surface 派生完整历史，于是同样的超限请求被反复发出，会话卡死。 |
| S-02 | 同次对话 | 口径确认：**轮次**含 0..N 个**步骤**，每个步骤是一次模型请求加它调用的工具；删除的单位必须是步骤，否则会破坏工具调用/结果配对。 |
| S-03 | 现有产品行为 | 分支只在最近一个已关闭轮次的页脚提供；删除/编辑模型可见消息没有任何入口。 |
| S-04 | 安装版调研 | DSH `0.2.2-rc.5`，`$DSH_HOME = ~/.dsh`。机制事实与证据见 §4。 |

## 2. 目标与非目标（草案）

**目标**

- G-01 不重建会话，把指定步骤及其之后的模型可见历史从上下文中移除，使超限会话恢复可用。
- G-02 按步骤边界分出新会话，用于「重做某步」或「跳过某步之后」。
- G-03 操作结果对模型可见部分可预期；原始日志保留，操作可审计。
- G-04 失败时给出可执行提示，而不是静默失败。
- G-05 操作入口在**对话页与轨迹页**都能发现并执行（v1 必做）。
- G-06 相关设置可在 **DSH 设置页**修改，不需要手改 `cordis.patch.yml`（v1 必做）。

**非目标（草案）**

- NG-01 不修改、不压缩会话日志文件本身（保持 append-only）。
- NG-02 不提供「从聊天界面彻底消失」的删除外观（见 RC-06）。
- NG-03 v1 不做任意中间步骤删除（只做后缀截断，见 RC-04）。
- NG-04 不做「撤销删除」（见 RC-09）。

## 3. 用户与场景

**主用户**：在公司内网 / 受限模型环境里使用 DSH 的开发者（S-01 当事人）。

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| U-01 | 读图步骤把上下文顶爆，会话卡死 | 截断到出问题的步骤之前，原会话继续可用 |
| U-02 | 某一步把模型带偏，想重来 | 从该步之前分出新会话，原会话保留 |
| U-03 | 想保留前面成果、丢掉后面步骤 | 从某步之后截断，直接给新指令 |
| U-04 | 在轨迹页核对每一步的请求/工具结果体积后直接操作 | 不切换页面即可选中步骤并截断/分支 |
| U-05 | 调整删除标记模式、默认范围等 | 在设置页改完立即生效，无需重启 |

**风险用户**：不熟悉轮次/步骤结构的普通用户——他们可能按「一条消息」理解删除，需要 UI 侧明确单位。

## 4. 调研与 PoC 结论

### 4.1 机制事实

证据路径以安装目录 `$DSH_HOME/node_modules/@deepseek-ai/` 为根。

| 编号 | 事实 | 证据 |
| --- | --- | --- |
| F-01 | 模型历史只从 surface 派生；`replace` 从未来请求移除被遮蔽条目，**不删除日志记录** | `dsh-session/README.zh.md:165`；`dsh/docs/subsystems/session.zh.md:321-342` |
| F-02 | compaction 的删除就是 `session.append('user/message', …, { surfaceOp: { op:'replace', startSeq, endSeq } })` | `dsh-compaction-basic/src/region.ts:506` |
| F-03 | 插件可注册用户命令，handler 拿到 `invocation.agent`（含 session），命令不经过模型请求 | `dsh/docs/subsystems/commands.zh.md:60-75` |
| F-04 | fork 接受**任意事件 seq** 作为包含式截断点；切在开着的轮次里由 Host 补 synthetic closer | `dsh-api-session-controller/src/commands.ts:230-264`；`dsh-session/src/fork.ts:28`；`dsh-session/src/repair.ts:66` |
| F-05 | 客户端已暴露 `sessions.fork({ sessionId, atSeq })`；现有 UI 只在最近轮次页脚调用 | `dsh-client-ui-chat/src/client/chat/TurnTailNodeView.tsx:70` |
| F-06 | 聊天视图只渲染 append surface 事件；替换事件默认不显示 | `dsh-client-ui-chat/src/client/conversation-nodes/message.ts:87`；`fallback.ts:16` |
| F-07 | 空内容的 system / developer / assistant 节点不派生 wire 消息 | `dsh-session/src/surface.ts:138-143` |
| F-08 | 第三方插件不能新增持久事件类型；元数据只能挂在既有事件的 message `source` 上（`MessageSourceMap` 可声明合并） | `dsh-agent-preset/skills/dsh-doc/references/practices.md:21`；`dsh-llm/src/message.ts:110` |
| F-09 | 设置服务把活动 profile 条目的 Config schema 投影成表单，`ctx.settings.configure({ auto: true })` 默认自动生成页面；字段写入走 profile patch | `dsh/docs/subsystems/settings.zh.md:5-11,33-38` |
| F-10 | 会话头部 `conversation.session.header.actions` 是 session 作用域的共享入口，切换 Chat/Trajectory 不影响；轨迹视图只暴露 `conversation.trajectory.images`，**没有行级 slot** | `dsh-cordis-client-runner/src/client/slot-catalog.ts:2036`、`:2368`；`dsh-client-ui-trajectory/src/client/*` |

### 4.2 PoC

| 编号 | 结论 | 状态 |
| --- | --- | --- |
| P-01 | 后缀截断可用：在内存 Session 里复现「读图步骤」，用空 `system/message` 替换到表末，`append` 接受，`deriveMessages()` 从 `user｜assistant｜assistant｜tool/image` 变为 `user｜assistant` | ✅ 已跑通，脚本见 [appendix/poc-surface-replace.mjs](appendix/poc-surface-replace.mjs) |
| P-02 | 真实会话端到端（Host 命令 + 运行中的 DSH） | ⬜ 未做，列入 Stage 4 验收 |
| P-03 | 自定义聊天节点是否被 `process-groups` 折叠隐藏；替换型 `user/message` 的自定义 Definition 是否只渲染一次 | ⬜ 未验证，影响 RC-05 的 UI 形态 |
| P-04 | 第三方插件只声明 Config schema 时，设置页是否自动出现该插件的表单；枚举字段是否可用 | ⬜ 未验证，影响 RC-10 的工作量 |

P-01 实测输出：

```text
before : user/text | assistant/text | assistant/text | tool/image
nodes  : 2,3,6,7
cut    : 6 .. 7
after  : user/text | assistant/text
nodes  : 2,3,9
replaceGen: 1
```

### 4.3 结论

- 后缀截断（RC-01）依赖最少、语义最确定，是 v1 的核心。
- 分支（RC-02）依赖现成 Host API，客户端即可发起。
- 「UI 上彻底消失」（RC-06）代价最高，不建议做。
- 无痕墓碑（RC-03 的 silent 模式）机制上成立，但属非常规用法，需真实会话验证。

### 6.1 若改为「轨迹页每项行内按钮」

轨迹页的行是 record（`user / assistant / message / tool / subtool / system / compacted`），不是 step；按钮只能挂在 step 范围内的 record 上，删除语义仍是「从该 record 所属步骤删到会话末尾」。

| 路径 | 做法 | 相对现状增量 | 代价 / 风险 |
| --- | --- | --- | --- |
| **A 遮蔽轨迹视图** | 插件用 `conversation.view` 的 `trajectory` id 替换 shipped 入口，把整包复制进来再加动作列 | **+10–15 人日**；每次 DSH 升级 **+1–2 人日** | 需复制 33 个 TS/TSX（≈11.0k 行）+ 8 个 CSS（≈2.9k 行）；虚拟化表格、8 语言、图片/复制/搜索/折叠全部要回归；实践禁止加载 Harness Client 包，**不能包装只能复制**，与 shipped 视图版本强耦合 |
| **B 本地补丁 DSH** | 在 `TrajectoryTable` 行内加一个 slot 或 context-menu target（约 50–100 行），插件注册按钮 | **+1.5–3 人日**；每次升级 **+0.5–1 人日** | 不再是可分发 bundle；升级会覆盖，需重放补丁；破坏「插件」形态 |
| **C 新增「步骤」视图 tab** | 插件注册自己的 `conversation.view`，用公共数据源渲染轻量列表，每行带删除 | **+3–5 人日** | 不是原轨迹页；只覆盖功能子集，列表/分组/折叠要自研；但升级安全、不复制 shipped 代码 |
| **D DOM 覆盖层** | 监听滚动把按钮浮在行上 | **+3–5 人日** | 表格用虚拟化 + 可变行高，按钮必然错位；违反「不要写组件外 DOM」实践；不可取 |

**结论**：现状（头部入口 + 面板）增量为 0；A 是整个 v1 客户端工作量的 2–3 倍，且带永久升级税；B 最便宜但不再是插件；C 是可接受的折中；D 不推荐。

## 7. 关键技术风险

| 编号 | 风险 | 触发条件 | 早期信号 | 缓解方向 |
| --- | --- | --- | --- | --- |
| R-01 | 截断后仍超限 | 保留的前缀本身已接近上限 | 下一次请求仍被网关拒 | dry-run 必须报估算与实际字节；支持再截一次 / 整轮范围（RC-04 变体） |
| R-02 | 会话卡在 running，命令无法执行 | 网关连接不返回、取消不生效 | `agent.status` 持续 `running` | 先取消；Stage 1 给出「取消失败」的诊断出口 |
| R-03 | 误截断不可撤销 | 轮次/步骤参数写错 | 截断后历史不符合预期 | dry-run 为默认演示步骤；可选「截断前自动 fork 备份」（D-06） |
| R-04 | 步骤→表层节点映射错误 | `user/message` 不带 turn/step，需扫描推导 | 找不到步骤 / 截断点偏移 | 以 `turn/start`、`step/start`、`step/end` 为边界写契约测试 |
| R-05 | 端点已被历史替换遮蔽 | 之前做过 compaction 或截断 | `append` 抛 "not found in surface" | 执行前校验端点仍是 surface 成员，失败给可操作提示 |
| R-06 | UI 入口被折叠隐藏 | 自定义节点被 `process-groups` 归入已完成轮次 | P-03 复现 | 改用侧栏面板（不依赖分组） |
| R-07 | DSH 升级导致 API 语义变化 | 升级到新版本 | `surfaceOp` / 命令 / 事件签名变更 | 锁定版本 + 按 `dsh-doc` 的升级清单核对 |
| R-08 | 日志体积不降 | 图片仍留在日志 | 会话文件持续变大 | 文档写明「只减请求、不减日志」；后续再评估归档 |
| R-09 | 网关按请求体积而非 token 限额 | 图片 base64 体积与 token 估算不一致 | dry-run 估算通过但仍被拒 | dry-run 同时报字节数与图片数 |
| R-10 | 与 compaction 并发 | 截断与 compaction 同时进行 | 端点失效 / 替换冲突 | 在同一个同步块内完成「读表层→校验→append」；只在 idle 且无 compaction 锁时执行 |
| R-11 | 轨迹视图无法行内操作 | 用户要求在轨迹表每一行直接操作 | 需要行级 slot，而 F-10 显示没有 | v1 用会话头部入口 + 步骤面板覆盖两个视图；行内需求另立阶段评估遮蔽成本 |
| R-12 | 设置页自动表单能力有限 | 需要联动字段、动态显隐或非 Config 状态 | P-04 发现表单表达不了 | 先用 Config 字段；必要时用 `settings.section` 自定义面板 |
| R-13 | 头部入口的浮层被裁剪 | 在 `header.actions` 内直接渲染下拉/弹出层 | 浮层被容器裁切（slot 文档要求 portal） | 浮层一律 portal 到 body；按 slot 文档的 overflow 说明实现 |
